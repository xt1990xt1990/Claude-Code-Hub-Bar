# 渠道名称搜索设计

## 目标

在“渠道”标签页增加即时名称搜索，帮助用户在当前选中分组内快速定位渠道，同时保持现有分组筛选、排序和渠道操作行为不变。

## 交互设计

- 搜索框位于渠道页顶部统计行的右侧，在“打开”按钮左边。
- 顶部排列保持为：渠道、启用、异常统计，弹性空白，搜索框，打开按钮。
- 搜索框使用紧凑宽度，显示放大镜图标，并在有输入时提供清空按钮。
- 输入后立即过滤，无需点击确认。
- 搜索词为空或仅包含空白时，显示当前分组内的全部渠道。
- 没有匹配结果时显示“没有匹配的渠道”；当前分组本身没有渠道时仍显示“暂无渠道”。

## 过滤语义

过滤顺序固定为：

1. 使用现有 `selectedProviderGroups` 计算当前分组内的渠道。
2. 在该结果中仅按渠道名称匹配搜索词。
3. 对最终结果应用现有置顶、启用状态和探测状态排序。
4. 渠道数、启用数和异常数均由最终结果计算。

名称匹配忽略搜索词首尾空白、大小写和音调符号。切换分组时保留搜索词，并立即在新分组范围内重新过滤。搜索词只保存在当前应用进程中，不写入用户偏好。

## 代码结构

- `MonitorState` 持有搜索词，并在搜索词、分组或渠道数据变化时重建现有 `providerFilterSnapshot`。
- 名称匹配提取为无副作用的纯函数，供状态层和独立测试共同使用。
- `ProvidersTabView` 只负责搜索框布局、绑定、清空操作和空状态文案，不重复实现过滤逻辑。

## 测试与验证

- 空搜索词返回输入集合。
- 名称匹配忽略首尾空白、大小写和音调符号。
- 不匹配的渠道被排除。
- 搜索只处理已由分组筛选得到的输入集合。
- 完整 Swift 独立测试、Node 测试、差异格式检查和 macOS Debug 构建通过。
- 启动最新 Debug 版本，人工确认搜索框位置、清空按钮、分组切换和统计数字。

## 不在本次范围

- 不搜索 API 地址、模型、渠道 ID 或分组名称。
- 不增加服务端搜索请求。
- 不持久化搜索历史或搜索词。
- 不改变现有分组的多选语义和渠道排序规则。
